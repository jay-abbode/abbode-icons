THREAD TREE CHANGE LOG  +  NEW ICONS
====================================

Includes the previous thread-config delivery's files, so this drops on top of
whatever state the repo is in.


1. THREAD TREE CHANGE LOG  (bottom of /webster/thread-config)
-------------------------------------------------------------
Every time the top 15 changes, it's recorded and shown at the bottom of the
page as a timeline, newest first. Each entry shows:

  - colors that came ON the tree (+ green chip)
  - colors that came OFF (- red chip)
  - colors that stayed but moved needle (Navy n7 -> n4)
  - coverage %, total uses, and the full needle order at that moment

Backed by a new THREAD_TREE_LOG tab, auto-created on first write — same
pattern as COMMENTS and MACHINE_CONFIGS. No new infrastructure, and the rows
stay readable in the sheet.

  A Recorded At | B Window | C Signature | D Coverage | E Total Uses
  F Summary | G Detail (JSON)

HOW "CHANGED" IS DEFINED: the signature is the needle-ORDERED slot list, so a
color moving from needle 2 to needle 5 counts as a change. That's deliberate —
it's a change you'd re-thread for. Same 15 in the same order = no entry.

Recording happens on page view (there's no cron for this page). Two people
loading at the same second could both append; identical consecutive rows are
collapsed on read, so a race shows as one entry. The write is best-effort and
wrapped — if the sheet write fails the page still renders and shows a small
warning banner instead of breaking.

First load with data writes a "Baseline recorded" entry, so there's always
something to diff against.


2. NEW ICONS  (/new)
--------------------
Everything added in the last 60 days, grouped This week / Last 30 / 31-60,
newest first, with a day count per icon. 30/60/90 day toggle at the top
(?days=N, capped at 365). Linked from the top nav and the hamburger.

WHERE THE DATE COMES FROM — this is the part worth reading, because the
catalog had no "added" date at all:

  1. SHEET — an optional "Date Added" column in MASTER. Authoritative when
     present. Also accepts headers: Added, Added On, Date Created, Created,
     Created On. Deliberately NOT a bare "Date" — too generic to guess at, and
     a wrong match would mis-date the whole catalog.
  2. DRIVE — the creation time of the icon's PNG, for every row that predates
     the column.

Sheet always wins, so re-uploading an old icon's PNG can't make it look new.

The Drive lookup does NOT ask per icon (that would be ~1000 round trips). It
asks a handful of icons which FOLDER their PNG is in, lists those folders once
(1000 files per call), and builds an id -> createdTime map — typically 3-5
calls for the whole catalog, cached 30 minutes. Stragglers get individual
lookups, hard-capped at 40 so a messy Drive can't stall a render.

The page states its own data coverage ("Dated 812 of 1,140 icons - 40 from the
sheet, 772 from Drive, 328 undated"), so an empty result is never mistakable
for a broken page.

GOING FORWARD: scripts/ensure_rows/ensure_rows.py now stamps today's date into
the Date Added column when that column exists. New flags: --date YYYY-MM-DD to
backdate a batch, --no-date to skip. If the column doesn't exist the script
prints a note and writes nothing — no behaviour change.

RECOMMENDED (optional, 30 seconds): add a "Date Added" column to MASTER row 2.
Everything works without it via the Drive fallback; adding it makes the dates
exact and removes the Drive dependency for new icons.


3. DOWNLOADS PAGE CRITERION  (/assets)
--------------------------------------
New "Scope" card above Categories: "Only icons added in the last 60 days".
Off by default — existing behaviour unchanged.

When on, it narrows the entire export: file counts, the ZIP contents, and each
category now shows how many of its icons qualify, with empty categories greyed
out and unselectable (so you can't tick a category and get an empty zip). The
scoped list feeds the same single code path the export already used, so the
checkbox can't drift from what actually lands in the ZIP.

The slug list is resolved server-side and passed in — dating an icon can need
a Drive call, which has no business running in the browser. If that resolution
fails the checkbox is disabled with an explanation rather than silently
producing wrong results.
